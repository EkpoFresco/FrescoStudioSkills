# Decisions Log

One line each: decision, then why. Newest at the bottom. Format: `D-NNN (phase) decision. Why.`

- D-001 (setup) Built the fork in the existing `Roblox Workfloq` folder via `git init` + fetch of upstream `main` (05ad7c8, v1.2.0), since the folder already held the prompt file. Why: avoids a nested clone; same result as a fresh clone.
- D-002 (setup) Renamed remote `origin` to `upstream` and set its push URL to `DISABLED-push-requires-approval`. Why: makes an accidental push impossible until the owner approves and adds their own remote.
- D-003 (research) Used the local Studio MCP tool cache (`%LOCALAPPDATA%\Roblox\StudioMCP\tools-cache.json`) as the primary source for MCP tools, dumped verbatim to `docs/roblox/studio-mcp-tools.md`. Why: it is exactly what this machine's Studio exposes, more reliable than web pages.
- D-004 (research) Ran Phase 2 as parallel research subagents, one output file each, while Phase 1 audit ran in the main session. Why: research is the longest phase; the prompt asks for parallel subagents.
- D-005 (research) Split implementation research into `implementation.md` (Luau, architecture, networking, exploits, performance) and `implementation-data.md` (DataStores, monetization APIs, analytics). Why: agents load only the half they need; keeps context small.
- D-006 (design) Distribute by copying a `studio/` payload into `~/.claude/` with a manifest, not as a plugin. Why: plugin skills are namespaced (`/rbx-studio:rbx-start`) and the bare form is unverified; rules and settings need a bootstrap anyway; the fork is not pushed so there is no marketplace host yet. Plugin packaging stays a later option.
- D-007 (design) Keep the prompt's agent names unprefixed; every description starts with "Roblox". Installer never overwrites a file it did not install (manifest + backup). Why: recognizable names; collisions handled by the installer instead of ugly prefixes.
- D-008 (design) Handoffs live at `.rbx-studio/handoffs/`, not `production/handoffs/`. Why: the global low-footprint rule (only `.rbx-studio/` in a game folder) beats the example path; configurable via `paths.handoffs`.
- D-009 (design) Path-scoped rules ship as `~/.claude/rules/rbx-*.md` with Luau-specific globs (`**/*.luau`, `src/{server,client,shared}/**`). Why: user-level `paths:` rules are native in Claude Code, load only when matching files are touched, so non-Roblox work is unaffected.
- D-010 (design) Hooks are one dispatcher per shell (`rbx-hook.sh` primary, `rbx-hook.ps1` twin), registered with an explicit `shell` field. Why: on this machine a bare `bash` from PowerShell is the WSL launcher; pinning the shell avoids that trap and supports machines without Git Bash.
- D-011 (design) Push/PR/merge approval comes from a `UserPromptSubmit` hook that sees the user's own words ("approved, push", `/rbx-ship`) and writes a session token; the `PreToolUse` gate checks it. Why: Claude cannot fake a user prompt, so the gate is real.
- D-012 (design) `skill-test` and `skill-improve` stay project-level in this repo (maintainer tools), not installed globally. Why: they test the studio itself; no game needs them.
- D-013 (process) Started the design doc while the last research agents finished. Why: structure depends on the install research (done); Roblox content only changes knowledge pointers, finalized after research lands.
- D-014 (research) Kept "QPTR over CTR" as the studio's core principle, but measured with today's signals: play-through rate (PTR), first-play bounce (<60 s, 61-180 s), and D1 / D2-7 / D8-28 retention of Recommended-For-You players. Why: Roblox replaced QPTR with PTR + bounce on 2026-06-15 (discovery-algorithm.md); the principle (qualified players who stay beat raw clicks) is unchanged.
- D-015 (research) `studio-mcp-tools.md` keeps Roblox's em dashes verbatim; the style linter skips it. Why: it is a primary-source dump, not studio prose.
- D-016 (build) Wrote agents and skills in the main session instead of fanning out to subagents. Why: one voice across 46 files, and the usage limit hit during research made extra subagent context expensive.
- D-017 (build) One install implementation: `install.ps1`. `install.sh` hands off to Windows PowerShell (Windows) or `pwsh` (macOS/Linux). Why: one code path to test; PowerShell is on every Windows machine and one `brew install powershell` away on macOS.
- D-018 (build) Installer hashes with .NET SHA256, not `Get-FileHash`. Why: in Windows PowerShell 5.1 launched from a pwsh environment the Utility module failed to autoload; .NET always works.
- D-019 (build) Hooks registered as shell-form commands with an explicit `shell` field (`bash "<home>/hooks/rbx-hook.sh" <event>` or `powershell -File ... <event>`), not exec form. Why: shell form works whether or not the host honors `args`; the explicit shell avoids the WSL `bash` trap.
- D-020 (2.1.0) Built a Roblox-aware project map (`tools/rbx-map.js`, `rbx-map.luau` for MCP-only games) instead of depending on graphify. Why: graphify's tree-sitter pass does not know remotes, DataStores, DataModel paths, or Luau `require` through instances; ours costs zero model tokens to build and joins remotes client to server. Graphify stays an optional extra for docs-heavy repos.
- D-021 (2.1.0) Hid 17 user-only skills with `disable-model-invocation: true` (incl. `rbx-ship`) and cut descriptions to budgets (skills <= 300 chars, agents <= 200), lint-enforced. Why: listings are paid by every session, Roblox or not (3,352 -> 857 tok). Verified live: the model sees 12 skills, all 29 stay typeable.
- D-022 (2.1.0) Library reads go through `tools/lib.js` (TL;DR + one section) and every agent carries a "Token rules" line. Why: library files are 8k-13k tokens; a section is 300-1,500.
- D-023 (2.1.0) Four tool-heavy agents (art-generator, qa-playtester, community-marketer, team-coordinator) run on Sonnet; judgment-heavy agents inherit. Why: cost without touching design or code quality.
